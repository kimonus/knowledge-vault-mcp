# Knowledge Vault completion and gap audit

**Date:** 2026-11-01. **Mode:** read only; no production assertion contents, database access, deployment, or curation. **Baseline:** GitHub `main` at `834e2c9b74bdea9e999d8842c3c08eb0c62fcc3e` (verified by fetch), the merge commit of [PR #69](https://github.com/kimonus/knowledge-vault-mcp/pull/69). The [post-merge CI run](https://github.com/kimonus/knowledge-vault-mcp/actions/runs/41350546472) completed successfully for exactly that SHA. This report does not treat a test, release, or earlier live snapshot as proof of current deployed behavior.

## Executive conclusion

**The original product goal is only partly achieved.** The server has a substantial, CI-tested foundation for durable, authenticated assertion storage, exact retries, correction, deletion, hybrid discovery, backup, and structured temporal resolution. It cannot establish that the client extracted all useful knowledge from a conversation, that a retrieved assertion is the right one, or that an assistant's answer is correct and cited. The new temporal resolver reconstructs state only for explicitly structured evidence; migration 0006 does not classify old assertions. The admin-only legacy attachment path added by PR #69 is tested on synthetic data but has no evidenced real-data review or deployed-path result. This is a product-completion gap, not evidence that the storage foundation is broken.

The historical [original brief](../../personal-knowledge-mcp-codex-prompt.md) specifies the outcome and definition of done. [AGENTS.md](../../AGENTS.md) supersedes its Secure MCP Tunnel transport with Cloudflare Tunnel/Access and private bearer-authenticated LAN/WireGuard access. The [roadmap](../architecture/knowledge-vault/roadmap.md), [work packages](../architecture/knowledge-vault/work-packages.md), and [older assessment](../architecture/knowledge-vault/assessment.md) are plans or snapshots. Their statements that temporal work is unmerged or that no quality harness exists are stale on this baseline.

**Status vocabulary:** *validated* means inspected implementation plus a passing relevant automated or documented independent test; it does not mean production validated. *Unverified* means the required evidence was not available in this audit. No extraction coverage, answer correctness, citation correctness, provenance completeness, production search latency, or deployed temporal success rate is currently measured by the cited reports. The synthetic measurements below are not estimates of those quantities.

## Legacy preservation and enrichment: unfinished end-to-end work

1. **Inventory without disclosure.** After authorized deployment, obtain aggregate temporal diagnostics and a bounded, admin-only ID/revision review queue. Distinguish no structured evidence, partial dates/provenance, and superseded chains; diagnostics alone do not label truth.
2. **Source adjudication.** For a small high-impact pilot, the operator checks the original source and successor chain, records whether supersession is a factual correction or a historical transition, exact identity/scope/value, source-observed time and precision, verification date, and any uncertainty. Never infer an effective date from import time or `status=current`.
3. **Preservation preview and approval.** Capture before snapshots of assertion IDs, content hashes, revisions, status, source links and temporal resolution output in an access-controlled operator store. Review a candidate payload and expected content hash; approve it with a separate admin credential. No bulk conversion from similarity or synthetic labels.
4. **Attach and read back.** Use `attach_reviewed_temporal_evidence` only where [the service checks](../../src/knowledge_vault/services/temporal.py) pass, including source-backed verified evidence and bounded validity for a historical transition. Verify the returned key, replay behavior, unchanged legacy row, evidence history, and both current and `as_of` outcomes. The implementation inserts evidence but cannot prove that the cited source supports it.
5. **Evaluate and recover.** Compare independently judged current/historical answers and citations before/after the pilot, including ambiguous/unknown cases. Keep a decision/audit record outside public artifacts. A wrong immutable attachment needs a reviewed corrective evidence operation or deliberate admin deletion path after preview; application rollback keeps evidence, while 0006 schema downgrade destroys it. Document the chosen correction and restored-result check before scaling the pilot.

The repository contains tests for synthetic preservation, race conflicts, idempotency, admin authorization and a 20-row fixture pilot. It does **not** contain evidence that this entire operator workflow has happened on real legacy assertions.

## Minimal completion plan and go/no-go gates

1. **Before the next release of PR #69:** maintainer reviews this audit and the PR's admin authorization, immutable payload checks, migration compatibility, and rollback notes; ensure the release candidate is based on `834e2c9` or a reviewed descendant. Follow [RELEASING.md](../../RELEASING.md): update version/changelog as appropriate, run a passing release rehearsal on that commit, check all required gates, build/sign/publish under the maintainer's separate release authorization. No M4/M5 schema is required for this release. **Go:** all required gates and rehearsal pass, rollback/backup plan is recorded, and release notes state that attachment does not auto-enrich legacy records. **No-go:** failed gate, incompatible rollback, or a claim that synthetic tests prove real legacy enrichment.
2. **T0 operational checkpoint after authorized deployment:** restore-test backup, apply/verify 0006 where needed, pin verified image digests, refresh actual clients, make authenticated MCP calls through the deployed path for both state and admin attachment on safe disposable/test evidence, including concurrent first use; inspect logs and restart counts. **Go:** documented commit/digest/schema/client versions, correct current/history and unknown/conflict results, unchanged legacy row, and healthy post-call logs/restarts. **No-go:** only rollout readiness, CI Inspector, or stale client schemas. Real assertion review is a separate authorization and stage.
3. **M1 independent quality gate:** two reviewers adjudicate source-first truth cards and run repeated, blinded client packets against disposable PG17/pgvector with the local production model; add consented operator-local real cases if feasible. Score source-processing and claim coverage, gold-seeded retrieval by language, temporal outcomes, grounded answers, citations and abstention separately, with denominators and uncertainty. **Go:** reproducible versioned report with independent labels and protected-slice results. **No-go:** template-only fake-vector scores or the scorer existing without judged runs. This is the recommended next verification milestone for the product.
4. **M2 decision only from M1 failures:** compare a guarded retrieval candidate on new frozen cases with the same real model and machine. Include no-record vector noise, multilingual slices, p95 and client abstention; use the [benchmark gates](../architecture/knowledge-vault/benchmark.md) provisionally until variance is known. **Go:** paired benefit without critical regression, within agreed latency/memory budget and with an easy rollback. **No-go:** no measured improvement, unacceptable false candidates or protected-slice loss. Then investigate extraction/client routing instead of changing ranking blindly.
5. **M3/M4 decision and controlled legacy pilot:** measure client source coverage first. If the ledger meets agreed coverage and replay needs, stop M3 before adding receipts. If high-impact current/history failures persist, conduct the source-backed legacy pilot above under explicit operator authorization; compare preserved rows and independently judged answers. **Go:** reviewed source support, correct precision and transition classification, exact readback, improved or safely unresolved answers, documented correction path. **No-go:** inferred dates, unreviewed supersession or missing preservation checks. Wider curation follows only after pilot evidence.
6. **M5 remains optional:** require observed stale/answer-feedback failures and a usable opt-in client workflow before any event receipt table or telemetry. **Go:** a labeled synthetic correction produces a regression case and passing re-evaluation, with privacy and idempotency tests. **No-go:** only retrieval/use counts or speculative freshness concerns.

The next release can ship the narrowly scoped reviewed-attachment code after its normal release gates; it must not advertise complete personal-knowledge retrieval or real legacy reconstruction. Deployed-path proof and real user evaluation necessarily occur with an authorized service and clients. Independent review should decide whether the report fairly represents the evidence before any implementation or curation begins.
