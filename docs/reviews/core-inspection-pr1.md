# Core inspection PR1 implementation evidence

Scope: accepted [ADR 0009](../decisions/0009-optional-read-only-dashboard.md), PR1 only. Design
PR #126 was merged after quality/supply-chain/Kubernetes/Inspector checks on the acceptance
commit; maintainer acceptance is linked from the ADR. No UI/browser auth/Helm dashboard
resources, deployment, infrastructure change or live credentials are part of PR1.

The implementation review must verify route confinement before both HTTP and MCP handling,
separate read-only session transactions/pool reuse, bounded query projections, cursor continuation
and unchanged ordinary-client behavior. Test data is synthetic and uses disposable pgvector
PostgreSQL; no personal vault or model weights are read. The optional inspection-principal list
is empty by default; no service credential is generated by these changes.

Security cases cover every registered ordinary HTTP route and MCP entry points, invalid and
mixed authorities, repeated/malformed headers, foreign Origin/cookies/Access assertions, route
normalization, unknown methods, cursor integrity/expiry/query/principal/audience/alias binding,
read-only SQL refusal and zero usage/maintenance records after inspection operations.

Traversal cases cover 653 assertions (above ranked candidate caps), all four statuses, lexical
enumeration, alias deduplication/null classifications, 110 sources/artifacts/identities/links,
both directions of supersession/conflicts, 1,003 raw evidence records, resolution overflow and
live insert/delete behavior. A 50,000-assertion synthetic case records keyset query plan and
browse/catalog samples; timings describe this test host, not a production guarantee.

The full suite exposed a pre-existing host-dependent evaluation test: its expected “missing
model root” error assumed the operator model directory did not exist. It now explicitly uses a
missing temporary root, preventing reads of operator-local state and making the intended safety
condition reproducible. No evaluation runtime behavior changed.

Remaining limits: live keysets are not snapshot exports; no complete metadata edit archive is
introduced; all single-user sensitivities remain visible; ranked search is candidate-limited;
inspection consumes existing core DB/model/rate resources. The core remains trusted with its
writer role; transaction read-only protection is additional to explicit operation/authority checks,
not a substitute for a separate DB privilege boundary. A future BFF gets no DB credentials.

This file records implementation/test scope, not an independent reviewer approval or deployment
security certification. Exact gate results and coverage are reported in the implementation PR.

## Local verification (2026-11-19)

- Full suite: **693 passed**, including unit/property/contract, disposable pgvector integration,
  e2e and the preceding published application against the current schema. One upstream pytest
  plugin deprecation warning remained. Application coverage: **98.05% statements** (4526/4616),
  **93.11% branches** (987/1060); separate threshold script passed.
- Lockfile check, Ruff formatting/lint, strict Pyright and Bandit passed. Installed locked
  dependencies had no known audit vulnerabilities; the local project itself is not a PyPI package.
- Helm lint/render for reference defaults and Cloudflare-enabled safe test values passed;
  strict kubeconform validated 28 resources across both renders, and rendered-number checks passed.
  No templates/images/migrations changed; no live server-side apply or deployment was attempted.
- Documentation links/fences/JSON and diff whitespace passed; no frontend/dashboard/chart files
  were added. CI still supplies its independent image/backup, secret and Inspector gates.

Synthetic timing host: x86_64 Intel Core i3-1315U, eight visible CPUs, Linux 7.0.0, local disposable
PostgreSQL 17/pgvector, deterministic fake embeddings and no worker/model downloads. Six 50k-row
samples: browse **6.49–8.62 ms**, canonical-topic catalog **300.80–311.50 ms**. All were below the
initial 500 ms query budget on this host. Six samples are not a production p95 estimate. Keyset
plan used the primary-key index (index-only key traversal); the catalog plan evaluated complete
filtered membership and distinct aggregates. No additional index/migration was justified.

An earlier catalog plan spent over 300 ms compiling JIT expressions and exceeded the proposed
budget. The final catalog transaction uses `SET LOCAL jit = off` and a grouped label CTE instead
of per-group correlated scans; ordinary core transactions retain their planner settings. API
credential-record validation runs at HTTP app construction, preserving workers that receive the
shared principal-list setting without mounting API bearer records. Both corrections are covered
by the final suite; no core/worker deployment configuration was changed.
